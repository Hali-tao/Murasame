# 记忆检索降级状态传入对话（2026-10-29）

基线 `c8590aa`。本轮接续用户对记忆和回复可靠性的意见，不改原需求、不调整语义模型/阈值，不继续角色制作。

## 已复现的问题

`MemoryService.recall` 在本地模型不可用或部分事实尚无索引时返回 `degraded: true`，但 `ConversationContext` 与对话提示只处理抛异常的分支，忽略了这个正常返回的失败/不完整状态。对话模型因此只收到空记忆，无法知道此次检索未完成；这增加了将“本轮找不到”误说成“用户没说过”的风险。另一个分支在数据库读取失败后清空内存快照，即使索引状态已标失败，召回仍可能返回 `degraded: false`。

原代码真实SQLite单元测试3失败、47通过：本地查询向量失败、部分索引提示遗漏、读取失败被当作健康空结果。实际旧包 `continuous-2026-10-29-uninstall-policy` 也复现：只在新建测试资料目录放入完整但损坏的用户模型覆盖文件，界面成功保存合成偏好、索引为0/1，对话仍能得到本地HTTP服务回复，但其真实请求没有传递检索失败说明。测试因此失败；没有损坏安装包模型或用户资料。

## 修改内容

- 传递召回的可选降级标记，并在系统提示中说明检索不完整或不可用，不能由未检出断言用户从未提过或没有偏好；关键背景无法确认时要求核实。
- 部分索引可用时继续传递真实找到的文本和ID，不丢弃有效记忆，也不伪造额外记忆。
- 存储加载失败明确标记召回降级。原抛异常分支、记忆禁用、正常空结果和正常召回语义保持。

这只修复提供给对话模型的状态和约束，**不能保证外部模型必然遵守，也没有证明实际回答质量整体提高**。docs/22的两项语义漏召回与独立留出集限制仍未解决；不降低阈值掩盖这些问题。
