# 从真实文件生成摘要

本次增量让任务能够读取明确来源、调用当前任务绑定的模型生成摘要、核对引用，再保存用户审阅过的准确内容。它补充原需求中的文件阅读与任务执行路径，不代表已经完成通用办公、编程或多个推理智能体的动态协作。

## 使用

先配置并验证可用模型，然后在“任务”中新建任务，例如：

> 请总结 "E:\工作资料\项目记录" 内 meeting.md 和 budget.txt，比较预算和进度，保存到 summary.md。

请写明授权目录、具体来源文件、摘要目的和新的输出文件名。含空格的目录请用引号包住。来源和输出都必须位于该目录内。当前这条摘要路径支持 UTF-8 的 `.txt`、`.md`；PDF、Word、目录自动遍历及代码执行仍属于后续增量，不能用本功能冒充完成。

1. **确认来源。** 检查完整文件清单、大小、修改时间、接收模型、服务地址、摘要用途和输出位置。批准后模型服务会收到这些文件的正文。当前阶段只生成草稿。
2. **审阅草稿。** 完整正文和逐段来源引用会显示在第二次审批里。第一阶段选择“本任务内有效”也不会跳过这次确认。桌宠的“审阅来源/审阅草稿”会带你进入任务页查看详情。
3. **批准保存。** 只新建这份准确的 Markdown 草稿，不覆盖已有文件。保存前重新核对来源，保存后从磁盘独立读取并比较字节与哈希。结果区显示真实产物路径。

每轮支持 1–5 个来源文件，单份不超过 32 KiB、合计不超过 64 KiB 和 24000 个字符；草稿不超过 12000 个字符。生成阶段包括排队在内最多 120 秒、最多 3 次实际模型请求。不会编造 token 数或费用。文件过大、编码不符或引用无法核对时会停止，并保留任务供补充要求。

## 取消与恢复

- 等待模型时仍可聊天。隐藏窗口不会取消文件摘要；在任务页明确取消才会停止后续操作。
- 取消时如果文件已经保存，会保留真实产物并说明已经发生的影响；不会把已保存的文件说成“什么都没做”。
- 拒绝或审批过期后，可在原任务点击“核对并继续”。保存阶段保留原草稿，不重复调用模型；来源变化则重新确认来源。
- 意外退出不会自动重发正文或重写文件。恢复时先查实际结果：目标与批准草稿一致则记为已保存；未出现则重新请求保存批准；不一致则受阻，不覆盖。
- 原任务绑定的模型配置被修改或删除时不会悄悄改用另一模型。请恢复原配置，或新建任务明确选择新的模型。

## 核验与数据范围

文件正文只在已批准的生成轮次中进入内存和模型请求，不存入普通工具调用日志、对话历史或长期记忆。用于审阅和恢复的草稿、必要引用片段及来源指纹保存在应用的加密数据库中。

引用核验确认“所引原文确实出现在本轮来源的指定行”，文件核验确认“保存字节就是批准内容”。这两项不能证明所有概括、推理或遗漏都绝对正确，仍需要审阅。文件里的命令、伪系统消息或工具 JSON 只作为资料，不会成为执行指令。
