# 自主活动页面跨入口状态同步

本轮接续 docs/21，基线 `1becfae`。改动只在自主活动页面和回归验证，不改变隔离权限、模型执行协议或原始需求。

## 复现与影响

在旧最终安装包内，先打开闲置的自主活动页面，再通过公开API启动真实离线代码活动。Docker成功启动，API成功返回，但页面仍显示“浏览网页/活动未开始”。旧页面没有订阅现有活动事件，闲置时也不轮询；只有本页按钮回调会主动刷新。

新增真实E2E在旧包失败：实际启动成功后，活动类型连续10秒仍为“浏览网页”，不是预期“写代码”。这是公开IPC入口的可复现同步缺陷；原正常本页启动按钮路径原本有自己的刷新，不扩大为所有正常启动都会失败。

## 改动

- 页面复用已存在的事件订阅和串行健康查询通道，从闲置开始跟随真实状态；迟到的旧查询不能覆盖新事件，卸载后停止查询与订阅。
- 状态仅由事件/健康通道更新，命令回执不再回写旧活动状态。操作归属及挂载保护防止晚到启动/导出回执覆盖停止或新操作。
- 明确区分准备结束时的中间闲置状态与真正停止。环境准备失败仍显示实际错误；明确停止事件会解除过期本地等待，不复活旧任务。
- 服务端没有改变的字段不反复覆盖用户草稿。晚到的首次历史状态、健康查询、启动过程中的空目标均保留未提交输入；真实新目标与活动信息照常同步。
- 准备、停止、清理未完成期间保持开始和范围开关锁定；准备可停止，停止中不可重复停止，清理失败后可重试停止。
- 健康读取失败时保留上次记录并明确提示，阻止新操作，停止仍可尝试。停止失败提示独立显示，不被“忙碌/断连”状态遮挡。
- 离线画面跟随活动身份重新加载，停止后消失。
