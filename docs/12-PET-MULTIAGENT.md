# 桌宠多智能体改进方案

> 2026-10-25 讨论定稿。这一版改的是产品重心和协同方式。
>
> 用户面对的是桌宠，不是控制台。模型是后端。多个智能体分工做事，桌宠负责派活、在场和把结果说出来。
>
> 本文是下一阶段的改进口径。`01-DECISIONS.md` 里已经生效的安全约束继续有效，尤其是 D-14（屏幕只解释、执行必须确认）、D-15（隔离环境默认不挂宿主目录，失效不得改到宿主上做）、D-18（结构化输出，核对者不看执行者的自述）、D-19（自主活动看路径是否完整、状态是否诚实，不把成功率当验收）。本文把「计划器只有四种工具」从实现天花板改成待替换的现状。

---

## 1. 现在的问题

这些问题是对着正在跑的程序说的，不是对照需求清单想象的。

### 1.1 开口的是大模型，不是桌宠

`conversation-service.ts` 的 `send()` 把用户每一句话直接交给当前对话接口。模型原文流式进气泡，再被朗读。系统提示词里只有诚实约束、关系阶段，以及角色的名字、性格和示例。这三项没填时，说话的就是接口那边的助手。

模型没配好时，这一轮直接失败。桌宠没有一套不依赖接口的在场方式：醒来、被点一下、告诉你「我还接不上模型」，都应该先存在。

### 1.2 多智能体协同从界面上看不见

用户说「能不能帮我在桌面随便生成一张图片」，得到的是模型自己的「没有这个能力」。原因有三层，都在代码里：

1. 回复先生成。分类发生在回复之后，用户已经看见模型的原话。
2. 分类只有 `chat` 和 `task`。提示词把任务限定成整理、修改、删除或运行。生成图片对不上，就当闲聊，不再创建任务。结构化分类失败时，退回的规则只认「整理、移动、删除、写入、创建任务、修复」。
3. 就算判成任务，计划器的工具也只有四种：按类型整理文件、在目录里跑一条命令、看 git 状态、读一个网页。提示词写明四种以外要追问、不要执行。没有「画一张图并保存到指定目录」这种队友。

所以协同只盖住了整理文件这一路。别的请求都是同一个模型在聊天。桌宠脚边即使出现状态，也只是任务页的一条摘要，看不出谁在做、做到哪一步。

### 1.3 控制台抢了桌宠的位置

密钥、记忆清单、完整记录、工具开关需要一个后台，这个后台可以留。但批准、进度、失败原因、做完之后的那句话，现在主要在控制台页面里。启动后控制台还挡在前面。用户装的是一个会干活的桌宠，不是管理后台。

### 1.4 干活的时候形象是静止的

正在执行时，桌宠几乎不动，旁边最多一句「正在做」。看不出它在看屏幕、在点、在等你确认，还是这一步失败了。隔离桌面的画面在控制台里，不跟着桌宠走。

### 1.5 相对 Codex 桌宠，缺的是「不用切走也能干活」

已经有的：浮在别的窗口上、拖动、缩放、记住位置、右键隐藏、快捷键唤起输入、文字和按住说话、一条状态（等你确认、没做成、正在做、做完了）、等待批准可以在桌宠上允许或先不做。

还缺的，按用户会感觉到的顺序：

- 多件事同时发生时，脚边是一组队友，不是一件事。点某一条就接着那件事，而不是打开整个任务页。做完未读的提示关掉应用后还在。聊天正在回复时也算「正在做」。
- 说话入口保持很小。形象下面是打字、说话、看进度，不要一点击就把窗口撑成一整条对话栏。
- 看屏幕和自己操作跟着桌宠。截当前画面可以进桌宠并开一段话，不必先把控制台拉到最前。隔离桌面的小窗贴在桌宠旁边，拖动时跟着走，可以收起。
- 换形象仍然用 Live2D，不改成生成精灵图。系统开了「减少动态效果」时，桌宠改为静止帧。

不照搬 Codex 的 `/pet` 命令、终端宠物，以及用生成图套用他人角色。

## 2. 这一版要变成什么样

一句话：用户对着桌宠说。桌宠决定叫谁。队友在各自的会话里做事，把事实交回来。桌宠用自己的短句说出来，并用动作和旁边的画面让你看见这一步。

模型仍然用现在的可配置接口。它不获得桌宠的身份，也不直接占用气泡。

控制台降为后台。启动时先只出现桌宠。控制台保留：模型与密钥、记忆清单、完整对话和任务记录、工具开关、导入形象、导出数据、日志。这些不挤进透明小窗。

## 3. 桌宠怎么说话

分三层。前两层不调用对话模型。

### 3.1 本地台词

醒来、单击、没接上模型、把事情交给某个队友、正在做、等你确认、做成了、没做成、技能被记住，使用本地句子，填入角色名和事实。接口不可用时这些句子仍然能说、能做动作。

本地句子不假装任务已经成功。没配模型时说的是「我在，需要模型的那件事现在做不了」，不是沉默，也不是一段助手式的道歉长文。

### 3.2 先分流，分流结果不给用户看

用户一句话进来，先判断交给谁。明显是文件、命令、看屏幕、去隔离桌面浏览的，不进闲聊。判断若要问模型，模型只返回标签和缺的那一个槽位（例如目录）。标签不进气泡、不朗读。

分流失败就按做不到处理，桌宠说明没分清，不把分类器的报错原文念出来，也不退回「让对话模型自由发挥」。

现有的 `recognizeIntent` 和 `chatIntentSchema`（只有 chat / task）不够用，要换成下面第 6 节的队友名单。关键词表可以留下当离线兜底，但不能再是唯一入口，也不能在兜底失败后假装这是闲聊。

### 3.3 闲聊才叫对话模型，由它给桌宠写一句短话

只有确认为闲聊时才调用对话接口。请模型写的是桌宠要说的一句短话：角色口吻、有长度上限、不要「当然可以」「作为 AI」这类助手腔。等这句完整回来再进气泡和朗读。等待期间桌宠播放在想的动作，不再把模型一个字一个字流进气泡。

模型原文可以留在会话记录里，供控制台查看。桌宠表面只显示那句短话。

任务做成、失败、需要批准，用队友交回的事实套本地句子。例如「移了 12 个，有 1 个被占用」。模型写的长总结不作为嘴。

## 4. 操作要让人看见

两层，不要把模型内部步骤演出来。

### 4.1 形象只表演正在发生的那一类动作

看屏幕、点击或打字、等待确认、失败停住、闲聊在想。思考、重试、算向量不做成动作。动作必须对得上真实的那一步：这一步失败了，形象停在失败上，不能继续播成功的动作。

### 4.2 改变了电脑的那一步，出现在桌宠旁边

点了哪里、打开了哪一页、写出了哪个文件，用一小块画面或一条刚发生的操作跟着桌宠。隔离桌面贴在旁边，拖动桌宠时跟着走，可以收起。一次整理很多文件时，形象保持在干活，旁边只留最近一步，展开才是整份清单。

这块画面默认不盖住用户正在看的内容，也不能变成关不掉的置顶层。收起后只留桌宠和一条状态。

## 5. 从 JiuwenSwarm 和 AgentArts 学什么

对照的是 openJiuwen 的 JiuwenSwarm（蜂群协作、Harness、JiuwenBox）和华为云智果 AgentArts（会话级隔离运行时）。学设计，不把产品搬进他们的框架或云上。

| 来源 | 学的点 | 落到 Murasame |
| --- | --- | --- |
| Harness | 模型负责想，外层负责任务循环、工具权限、子代理、停止条件 | 桌宠是这层外壳。`send()` 不再直接 `gateway.chat()` |
| Leader / Teammate | 主代理拆任务，队友用单独会话，交回证据 | 第 6 节的名册。核对者只读 |
| 任务单 | 目标、允许的工具、步数或时长上限、完成条件 | 第 7 节的字段。桌宠和跨进程队友用同一张单 |
| 权限 | 执行前允许一次、本任务允许、或拒绝 | 沿用现有批准。范围变了必须再问 |
| JiuwenBox / AgentArts 会话沙箱 | 一间任务一间房，规定目录和网络，做完拆掉 | 会改电脑的操作进现有 Docker 隔离桌面。不在 Linux 上重做 bubblewrap |
| 技能自演进 | 失败或用户不满后，把走通的步骤沉淀成可复用技能 | 第 8 节。技能不能扩大权限 |
| AgentArts 的云上扩容、ARM 镜像、企业网关 | 不搬 | 桌宠跑在用户自己的 Windows 上 |

分布式蜂群在这一版的意思是：队友可以不在桌宠这一个函数里。隔离容器已经是另一名队友。以后要跨机器，发的仍是同一张任务单，不另做一套协议。第一阶段允许队友都在本机进程里，但会话和权限必须分开，否则只是一个模型扮演多个人。

## 6. 队友名册

四种工具不够。下面每一名都有单独会话、允许的工具和交回的事实格式。桌宠可以同时派几名，脚边按「等你确认、没做成、正在做、做完了」排序。还有别的在等时要写明件数。

| 队友 | 做什么 | 不允许做什么 | 交回的事实 |
| --- | --- | --- | --- |
| 桌宠（Leader） | 听用户说、分流、本地台词、表演、把事实说出来 | 不自己改文件、不自己点隔离桌面 | 说了哪句、叫了谁 |
| 桌面与文件 | 在用户点名的目录里创建、保存、移动、列出。包括把生成的图片保存到桌面 | 不碰未授权目录；删除仍要单独批准 | 路径、字节数、成功几项、失败几项及原因 |
| 命令 | 在隔离环境里运行一条命令。生成图片走这里：命令写出文件，再由核对者证明文件存在 | 不在宿主上直接跑。隔离失效时停止，不改到宿主 | 命令摘要、退出码、产出的文件路径 |
| 屏幕 | 看当前前台窗口，解释画面 | 不执行。要变成操作时必须先确认，确认后交给隔离桌面或文件队友 | 窗口标题、看到的内容、不确定的地方 |
| 隔离桌面 | 打开网页、点击、输入、看视频。小窗跟着桌宠 | 默认不挂宿主目录。失效就停 | 打开的地址、点过的步骤、最后看到的画面 |
| 记忆 | 提取和召回偏好 | 不执行文件和命令。沿用 D-22 的只读加记忆目录 | 新增、更新、失效了哪几条 |
| 核对 | 只读检查：文件在不在、大小对不对、页面是不是开着 | 不能改文件，也不能相信执行者的自述。沿用 D-18 | 证据与结论：通过、部分通过、失败 |

「在桌面生成一张图片」的走法应当是：

1. 桌宠说「我让命令去画，画完先放在隔离环境里，再问你要不要拷到桌面。」
2. 命令队友在隔离环境里生成文件。
3. 核对队友确认文件存在且不是空文件。
4. 桌宠说明结果。用户同意后，文件队友才把这一份拷到用户点名的桌面目录。
5. 任何一步失败，桌宠说失败原因，形象停住。不允许对话模型抢先说「我没有这个能力」把流程盖掉。若隔离环境不可用，桌宠直接说现在画不了，因为隔离环境没准备好。

闲聊不占用上面任何队友。

## 7. 任务单

桌宠派活和以后跨进程、跨机器，都用这一张单。字段保持少，但缺一不可。

| 字段 | 含义 |
| --- | --- |
| `id` | 这一次委派 |
| `goal` | 用户原话里的目标，不改写成已经完成 |
| `teammate` | 第 6 节的一名 |
| `allowedTools` | 这一张单允许的工具。超出即拒绝 |
| `workspace` | 隔离环境，或用户点名的一个目录。未点名不得猜一个去写 |
| `limits` | 步数、时长。到了就停，并说明停在哪 |
| `needsApproval` | 动用户文件、删除、联网范围变化时为真 |
| `skillId` | 可空。命中了已有技能时带上，见第 8 节 |
| `parentId` | 谁派的。核对单的父单是执行单 |

队友交回的不是聊天段落，是结果单：

| 字段 | 含义 |
| --- | --- |
| `status` | 完成、部分完成、失败、等待批准、正在停止 |
| `facts` | 可核对的短事实：路径、数量、退出码、看到的标题 |
| `evidence` | 截图、文件大小或哈希。给核对者和桌宠旁边的画面用 |
| `error` | 失败原因。空表示没有失败 |
| `skillUpdate` | 可空。建议写成或改写哪条技能。不自动生效，见第 8 节 |

桌宠只朗读由 `facts` 和 `error` 填出来的本地句子。`facts` 为空又声称完成，按失败处理。

停止沿用现有规则：用户取消后状态是「正在停止」，不再开始新的一步。已经写出去的那一步不假装没发生。

## 8. 技能自演进

技能是本地的一份做法，不是新的权限，也不是另一段会自己变长的系统提示词。

一条技能至少包括：适用的目标说法、使用的队友、允许的工具、步骤、怎样算做成（核对者用的检查）、上次失败的原因。放在本机用户数据目录，不进安装包，不同步到别人的电脑。

什么时候写：

- 一次任务走通，并且核对通过。桌宠说「这种做法我记下了」。
- 用户纠正，例如「不要放桌面，放图片文件夹」。原技能标成被取代，新技能另写一条。旧的留着可追溯，不物理抹掉。
- 失败不写成成功技能。失败原因可以附在技能上，避免下次用同一条死路。

什么时候用：

分流时先找技能。命中了就带上 `skillId`，队友按技能的步骤做，仍要受 `allowedTools` 和批准约束。技能若要求当前单子里没有的工具或目录，忽略这条技能，桌宠说明「上次的做法越出了这次允许的范围，我按这次的限制做」。

技能不能：

- 给自己增加工具或目录。
- 关掉批准。
- 修改核对标准去迎合失败的结果。
- 在用户没同意时覆盖角色的说话方式。

这一版不做技能市场，也不做自动改模型权重。演进的只是本地步骤。

## 9. 沙箱和安全

会改变环境的操作默认发生在 D-15 的隔离桌面里：默认不挂宿主目录，独立网络，失效不得改到宿主上做。

文件队友只有在用户点名一个目录并且批准之后，才能写那一个目录。生成图片先出现在隔离环境，拷到桌面是第二次批准，避免模型一句「写到桌面」就碰用户的真实桌面。

屏幕、网页、命令输出里的文字仍是不可信观察，不能当成新的指令，也不能据此扩大权限。这一点保持现有提示词里的约束。

核对队友不接收执行者的自述作为通过依据。通过只认证据：文件存在且非空、退出码、截图里的窗口标题。

控制台里的工具开关继续有效。关掉的工具不会出现在 `allowedTools` 里。

## 10. 桌宠脚边的状态

同时只突出最要紧的一条，其余收在同一组里：

1. 等你确认
2. 没做成
3. 正在做（含对话模型正在写那句短话、某名队友正在执行）
4. 做完了但还没看

等你确认的那一条上可以直接「允许」或「先不做」。点某一条打开的是这件事的经过和画面，不是整个控制台首页。做完了可以收起。正在做不能被收起盖住。关掉应用再打开，未读的「做完了」和「没做成」还在，直到用户看过或收起。

## 11. 和当前代码的对应

| 现在 | 这一版 |
| --- | --- |
| `send()` 先 `gateway.chat()`，原文进气泡 | 先本地分流。闲聊才要一句短话。气泡不流式播放模型原文 |
| `chatIntentSchema` 只有 chat / task | 分流到第 6 节的队友 |
| 计划器四种工具，其余要求追问 | 名册替换这四种。整理文件只是「桌面与文件」的一种做法 |
| 分类失败退回关键词，对不上就当闲聊 | 对不上就说没分清或没有这名队友，不让对话模型冒充答案 |
| 任务状态主要在控制台 | 桌宠脚边一组队友。控制台留记录和设置 |
| 隔离画面在控制台页 | 小窗跟着桌宠，可收起 |
| 没有技能 | 第 8 节，本地、可追溯、不能扩权 |
| 形象不随真实步骤变化 | 第 4 节。失败就停在失败 |

不在这一版假装已经做成的：跨机器部署、技能在用户之间流通、用一句话生成新的 Live2D 形象、把自动化成功率做到稳定成功。D-19 仍然有效，隔离桌面里的点击会失败，失败必须照实显示。

## 12. 建议的实现顺序

1. 本地台词和分流前移。没配模型时桌宠仍能在场。生成图片这类句子不再被对话模型抢答。
2. 任务单和结果单。桌宠只念事实。脚边从一条状态改成一组队友，未读在重启后还在。
3. 补队友：桌面与文件、隔离环境里的命令、核对。打通「生成一张图片 → 核对文件 → 问过再拷到桌面」。
4. 隔离画面跟着桌宠。形象动作对准真实步骤。
5. 技能：走通并核对通过之后可以记下，下次命中。越权的技能不执行。
6. 屏幕队友和隔离桌面队友并入同一套任务单。控制台默认不在启动时挡在前面。

每一步都要能单独演示。做不到的那一步，桌宠说做不到，不显示成完成。

## 13. 这一轮已经落地的部分

2026-10-25 改进方案里、除明确不做的跨机器部署以外，都已接到当前程序。

- `send()` 先按队友分流。生成图片、整理文件、看屏幕、打开网页、改保存位置，都不再先调用对话模型。
- 闲聊仍然调用模型，但等整句回来再显示，并要求它只写一句桌宠的短话。模型没接上时，这句失败说明是桌宠的本地台词，不会写成一条成功回复。
- 生成图片：隔离容器没开就直说没画，并记在技能的失败原因上，不写成成功做法。开了就写入一张 PNG，核对者只看 `stat` 的字节数。通过之后任务停在「等你确认」，允许才拷到桌面或图片文件夹，拷完再核对宿主机上的文件。
- 技能写在本机 `skills.json`。旧做法标成被取代，不删。工具超出这次允许范围就不用，桌宠会说按这次的限制做。说「不要放桌面，放到图片文件夹」只改目的地，仍然要你点允许。
- 形象按这一步表演：看屏幕是在看，打开网页是在动，等你确认是停下来问，失败停在否定上。队友这几步不再交给模型猜表情。
- 隔离桌面一旦有画面，小窗贴在桌宠右上角，拖动桌宠时跟着走，可以收起。
- 桌宠脚边最多四名队友。正在等模型写闲聊那句时，也会显示「正在想」。点某一条会打开控制台里的这一件，不是整个首页。收起过的完成和失败记在本机，重启还在。
- 引导做完之后，启动不再把控制台自动摆到前面。桌宠菜单和托盘仍能打开它。
- 系统开启「减少动态效果」时，桌宠停在静止帧。

这一版仍然不做：跨机器发任务单、技能拿去给别人用、用一句话生成新的 Live2D。隔离桌面里的点击会失败，失败照实说。生成出来的是程序画的小色块图，用来证明文件真的写出来了。
