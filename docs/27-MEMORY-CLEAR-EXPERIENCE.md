## 审阅发现与补修

独立只读审阅没有认定初始界面/提示改动存在阻塞缺陷，但指出未评估既有 `clearSource` 永久停用会话来源的行为。主代理继续检查发现这会使保留的会话无法学习后续新事实，不能只按“旧代码未改”排除：列为重要问题，在本轮补修。

裁定：清除某会话的记忆只取消清除前已在途/排队的提取，保留会话仍能学习未来新事实；已删除事实继续受抑制表保护。删除历史真正成功后才永久停用来源，失败时保留会话的后续提取能力。这遵循 D-04 的历史/记忆独立性，不放宽旧事实复活规则。

- 两项真实SQLite测试在修改前失败：清理成功后未来事实被跳过；事务清除失败后待处理/后续提取仍被停用。另一个核心测试复现历史删除失败后未来提取被跳过。修复后这两文件 **55项通过**。
- 采用每来源清理版本取消旧提取，清除事务失败回退版本；真正删除历史成功后才设永久停用。SQLite失败使用受控触发器中断事务，验证回滚和重新创建服务读取，不等同于物理磁盘损坏恢复。
- 中间包先通过原来的两个新增UI流程。第三项流程首次误将欢迎消息算入回复数量，错误安排原样保存；纠正为实际流式回复数量后，中间包在“清理后新事实不存在”断言明确失败。
- 修复后的最终全仓 **65文件796项通过**，类型/lint/追踪74项通过。最终独立包改用 `continuous-2026-10-29-memory-clear-ui-final`；中间包保留供失败证据核对，不作为最终交付。

审阅提出的三个低优先级测试补强仍留后续：按来源清除时提示与迟到结果的完整组合、清除响应返回前启动新一轮时保留新提示、提示监听器自身抛错。当前对应代码经只读检查；新增真实SQLite场景覆盖其中的数据取消部分，不能替代所有提示组合。
