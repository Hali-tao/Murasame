# 来源语境召回实验（2026-10-29）

本轮接续docs/22的“保留来源语境”假设，**没有修改生产检索、提取提示、用户资料或安装包**。起点06ebcdf，角色制作继续暂停。原南京散步和Rust所有权两项漏召回仍未解决。

## 方法与提前固定的条件

在运行模型前固定54个合成问题和14条事实：开发组6事实/18问，独立实体验证组8事实/36问。每条事实同时有短版本和包含明确来源关联的版本，例如“我住在成都”与“我住在成都，周末想在离家不远的地方骑车或者逛绿道”。关联是预先写入的合成来源，不是模型从外部知识替用户推断的背景。

两个版本均调用真实本地BGE和生产recallMemories，保持cls-q8-l2-v1、0.45阈值、8条与现行预算。使用相同查询，不改模型或阈值，不做查询重写，不引入云端服务。预先规定：两组直接命中不得下降、验证组间接命中必须提高、两组负例侵入不得增加。开发组和验证组均在看模型结果前写定；本轮不按结果调参或修改标签，不能声称这是大型独立盲测。

负例明确标为无需个人背景的通用知识、翻译、计数或字符串操作；任何个人事实进入这些负例都计作侵入。这是本实验的保守评价规则，不等于有完整人工相关性标注的实际用户回答质量。正例只检查指定事实是否进入实际注入列表，不据此宣称整体precision。

## 结果

| 资料组与版本 | 直接事实命中 | 间接语境命中 | 负例带入个人事实 |
| --- | ---: | ---: | ---: |
| 开发组：短事实 | 6/6 | 1/6 | 1/6 |
| 开发组：来源语境 | 6/6 | 6/6 | 2/6 |
| 验证组：短事实 | 8/8 | 10/16 | 3/12 |
| 验证组：来源语境 | 8/8 | 16/16 | 8/12 |

保留语境提高了本批间接问题命中，但两个组的负例侵入都增加，**未达到预先规定的采用门槛，候选拒绝进入产品**。这不证明来源语境一概不可用，只说明不能将“把更长来源直接作为记忆文本重新编码”不加区分地推广。

上下文版本由人工合成并直接提供；本轮没有实现或验证自动提取能正确保留这些关系、来源绑定正确性、错误来源防护或旧索引迁移。两种版本携带的信息量不同，收益不能归因于纯粹增加字数。

具体新增侵入包括：“把字符串macos改成大写”带入Kotlin和macOS背景；牛奶价格计算带入乳糖限制；字数统计带入居住城市和观鸟爱好。另一个例子“brew这个英语动词是什么意思”的设备相似度只有0.372，仍因Homebrew文本的关键词子串通道进入列表。这说明语义和关键词通道都需要检查，不能只看命中率或只调语义阈值。

## 验证与边界

使用新的独立输出目录从最终归档脚本重跑一次，54问的命中、注入ID和负例判断全部一致；两次网络尝试均为0。固定资料SHA、生产检索源码与模型文件SHA及上一轮最终安装器指纹核对一致。脚本只将临时编译模块写入previews/tmp，不写out或生产资料目录。

证据位于 `artifacts/continuous-24h-2026-10-29/memory-source-context/`，包含原始资料、首次运行前指纹、逐问排名和向量、复跑结果、检查脚本与验证回执。脚本退出0表示评测流程完成，`candidateAccepted:false`才是质量结论；不把诊断成功当成软件质量达标。本轮没有跑完整产品测试或重新打包，因为没有生产修改；868项和最终包32项属于上一轮交付，不冒充本轮新增验收。

后续需要分别验证“明确个性化请求”和“仅操作引用文本”的检索边界，并在保留来源语境时防止同词不同义的背景污染。不能基于这54问直接写死词表或只修城市/编程语言两种特例；下一候选仍要先固定新的对照问题，再决定是否进入生产。真实外部模型回答评测、完整任务协作、安装链及全天稳定性仍未完成。
