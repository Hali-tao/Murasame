# 卸载默认保留与升级提示修复（2026-10-29）

基线 `7aa5988`，接续同事 issue #2 的安装/数据保留排查。原要求 docs/01 D-13 是卸载默认保留、可明确选择删除；没有改变需求或关闭 issue。角色制作按用户最新要求继续暂停。

## 已复现的缺陷与修复范围

旧 `build/installer.nsh` 的确认框缺少 `MB_DEFBUTTON2`，默认落在“是/删除”。electron-builder 的替换安装会调用旧卸载器，且在其升级判断之前执行 `customUnInstall`；原自定义代码没有避开静默/升级，也没有静默默认回答。独立原生 NSIS 运行中，普通静默、静默升级、带升级标记三种场景全部停在提示处，超时而未完成。

修复让这个自定义钩子在普通静默及升级调用中直接保留资料；手动确认默认选“否”，静默后备回答也是“否”，未匹配回答不会落入删除分支。手动明确选择“是”仍沿用原删除功能。默认保留是产品要求，不是测试策略。

本轮没有禁止 electron-builder 原有的显式 `--delete-app-data` 命令行选项。该选项会在自定义钩子之后另行删除，属于调用者明确要求删除的例外；不声称普通静默/升级保留测试覆盖了该选项，或把相互矛盾的标记组合当成已支持流程。

**已有旧版本的首次升级仍有限制**：替换安装运行的是已安装版本的旧卸载程序，不能由新源码反向修复。旧提示若出现，应选择“否”保留数据。新包写入的卸载程序才具备本轮保护；不能把新包编译成功称为所有历史版本升级都已通过。

## 验证方法与真实边界

`scripts/verify-uninstall-hook.mjs` 使用项目实际 NSIS 编译器及 StdUtils，读取生产钩子，仅将其固定数据目录替换为本次新建的合成目录。未写注册表、快捷方式或安装真实应用。每次生成数据库名、密钥名、Local State 和日志四个合成文件，比较运行前后 SHA-256，并检查钩子返回标记。阻塞时只停止本次拥有的测试进程，不操作真实资料。

旧源码三项全部失败；新源码三项全部通过。完整 `npm run verify` 为 **68 文件 842 项通过**，类型检查、ESLint 和 74 项追踪映射通过。追踪映射只是关联，不是全部 SRS 验收。

原生测试工具最初遇到中文绝对 include 路径编译失败，改用相对 include 后才形成有效的产品失败证据；原始编译失败也保留。桌面操作工具和备用入口均在初始化时返回 `failed to write kernel assets / os error 3`，没有完成鼠标/键盘交互。默认“否”已通过实际编译和官方 NSIS 标记语义核实，**尚未实际按回车验收**；明确选是/否、外部文件锁导致部分删除、完整卸载→重装→清理→重启仍待隔离 Windows 环境验证。

独立只读审阅指出框架还支持显式 `--delete-app-data`。作者核对原 D-13 后将其保留为明确删除例外，收窄本轮结论，不增加未经要求的命令行限制。审阅列出的手动交互、首次旧版本升级和部分删除边界均未从待办中删除。
