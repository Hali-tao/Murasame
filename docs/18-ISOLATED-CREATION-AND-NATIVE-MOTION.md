# 隔离创作、通知与原生动作增量

本轮依据原SRS的FR28–30/UC10推进真实办公与编程闭环，不改变原要求。此处记录已实现范围及剩余缺口，不代表通用办公、完整项目开发或全部多智能体协同已经完成。

## 使用路径

在自主活动选择「办公文档」或「Python编程」，确认本次隔离范围，开始后输入目标并点击「开始创作」。默认模型必须已经验证文字与工具调用能力；同次创作和独立审阅固定使用该模型的快照，不被中途更换默认服务改变。

1. Worker生成候选。办公正文为纯文字；Python为自包含标准库脚本。
2. 办公使用真实LibreOffice保存ODT并回读正文；Python使用独立普通用户实际运行，记录退出状态与输出。文件字节、SHA-256与候选逐项核对，真实失败不能被模型口头成功覆盖。
3. Critic用独立请求检查原目标、候选与真实证据。可要求一次修订；最多两个候选、六次实际模型发送，结构重试也计数，总创作180秒。活动原有10分钟/12动作上限保持。
4. 通过后在真实隔离桌面打开文件，并显示正文/代码、实际输出、审阅与文件校验值。点击「选择位置并保存」后由原生保存窗口选择目标，再次回读核对内容，仅新建文件、不覆盖现有资料。

停止或到期会清理容器，需提前导出。界面离页重入会恢复活动类型、目标、联网范围和阶段；清理失败保留重试停止入口。导出错误和取消结果不会被后台状态刷新覆盖。

## 执行与显示边界

- 无宿主挂载或设备透传，不暗中读取用户文件。隔离桌面联网独立控制；主动输入的文字目标仍会发送到已选模型，界面已说明。锁屏、免打扰及取消在发送、执行、返回和导出边界检查。
- 候选代码以`murasame-code`独立非root身份运行，核验程序与收集文件不由该身份写入；脚本本身不联网、不能连接容器内编辑器/桌面服务或启动子进程。单次代码15秒，CPU/内存/输出/文件句柄有界。固定核验脚本以Python隔离模式运行。文档显式编码/回读ODF空白，连续空格与制表符完整保留。
- 联网活动继续使用原noVNC交互画面。Docker的`network none`不能通过发布端口显示VNC，离线创作因此使用容器真实截图，每5秒串行更新、只查看；不会为了画面而偷偷开放网络。离页、停止和许可暂停不保留迟到画面。这还不是离线交互式VNC。
- LibreOffice与code-server同时放入schema 3镜像；旧镜像会明确要求升级。code-server固定官方4.143.1发行包和SHA-256。编辑器用官方`payload/openFile`方式打开已生成文件。参考：[官方安装说明](https://coder.com/docs/code-server/install)、[官方文件链接说明](https://coder.com/docs/code-server/FAQ)、[LibreOffice启动参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)。
- 本机原`murasame-isolation:local`已保留为`murasame-isolation:pre-fifth-20261029`，验证的新镜像另有`murasame-isolation:fifth-20261029`标签。没有删除用户其他镜像或容器。
