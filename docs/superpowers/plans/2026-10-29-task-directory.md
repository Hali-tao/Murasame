# 明确任务目录与 Windows 路径一致性

本轮依据用户自主迭代授权执行，不修改原始需求。基线 e10f25f，所有原有审批与摘要恢复约束保留。另两条独立工作线负责对话/记忆和原生奶龙连续性；本计划只负责任务目录路径与界面接线。

## 问题与决定

- 当前 `E:\` 被去掉最后分隔符后成为 `E:`，可能按进程当前目录解析；同一目录的 `/`、`\`、大小写与尾分隔符也可能被误判不一致。用统一的绝对目录规范化与比较，不将驱动器相对路径、设备路径或根相对路径猜成授权目录。
- 创建计划时没有用户确认目录，普通产物清单仍可能相对进程目录计算 baselineHash。未确定根目录前仅保存计划建议，不扫描文件或捕获产物基线。
- 新建任务增加可选“选择工作目录”，使用现有原生目录选择器；选定目录通过独立 IPC 字段传给主进程。主进程验证目录后给 Planner 明确范围，并独立核对模型计划；不能因模型猜了路径就授权。
- 待确认任务提供“选择目录并继续”，选定目录是这次明确补充信息；后续敏感动作仍单独批准。
- Planner 的常用目录提示使用系统真实 desktop/downloads/documents 路径（含重定向）；无法读取时明确让用户选择，不假定 homedir 下就是实际桌面。

## 验收

1. RED→GREEN：盘符根、斜线/大小写等价、含空格引号目录、多路径文本的先后位置；非法相对/设备路径拒绝。
2. 真实 TaskService + SQLite + 临时文件：所选目录传到 Planner/Task scope/实际审批；模型越权目录被拒绝；无目录时不捕获文件 hash；确认后再捕获；继续任务不得更改到与实际确认目录不同的模型 root。
3. 原生目录选择取消不创建任务/改变目录；UI 与 IPC 能完整传递所选目录。真实 Electron 通过目录选择器边界 fixture，做实际文件任务并检查两次摘要审批不受影响。
4. 最后统一两端类型、lint、全量单测、build 和适当 Electron 验证；独立审查重要问题闭环后普通提交并推送 GitHub main。

## 分工和限制

主任务：task-root/executor、TaskService、IPC/types/preload/store、任务页/新建任务对话框、MurasameCore 的目录提示。其他代理不改这些文件；集成时不覆盖对话/记忆或原生角色改动。

工作时 TEMP/TMP 使用 previews/tmp。只使用独立测试文件；真实用户资料和旧安装包不动。全部检查通过前不提交。07:45不新增大改。
