# 对话记忆检索状态设计

依据用户的软件自主迭代授权及docs/31已记录缺口，由实施者决定此小型增量；没有请求或声称用户逐字批准此设计。角色制作继续暂停。

目标：用户无需依赖模型措辞，便能判断最近一次已完成回复的记忆检索是否完整。保持现有上下文面板和召回ID，关联会话与回复，刷新/重新读取后保留。正在发送的回复、失败请求不能替换上次成功记录。

方案：沿用已持久化的prompt调用记录，在同一JSON参数中增加状态；现有Conversation更新通道带到UI，不新增全局toast或数据库表。全局告警容易串会话，纯页面临时状态会在刷新后丢失，因此选用随回复保存的上下文说明。此选择由实施者作出。

状态契约：`complete`正常完成，`limited`正常返回但degraded，`unavailable`抛异常或缺少检索服务，`disabled`该次记忆未启用，`not-used`交给任务/工具而未检索，`unknown`旧记录缺字段或无法识别。没有prompt记录时不猜测过去状态。正常完成且ID为空显示“未找到相关记忆”；有ID显示“已使用记忆”。有限/不可用用琥珀色说明，仍展示实际召回条目；已删除条目沿用既有提示。设置改变不重写过去状态。

UI：上下文卡注明“最近一次已完成回复”，增加独立状态块，文本明确指向“该次回复”。未记录和旧状态不能显示为成功。关闭上下文面板保持原行为，不增加弹窗或依赖开发术语。

范围：只增加状态持久化与显示；不改变记忆召回策略、模型、阈值、提取、语音、任务执行或角色素材。不把模型遵循提示、语义准确率、完整SRS验收计为完成。

验收：真实SQLite状态/旧记录/失败回滚；组件状态切换、删除后保留提示、折叠；旧包损坏本地模型场景先缺失UI而失败，新包真实IPC/HTTP流程及正常BGE都通过，刷新与切换新会话不串状态。保持原安装器和用户资料。
