# 奶龙三维角色：整体造型优先

用户于2026-10-29明确回复“按照你说的来，可以走三维路线”。此授权恢复独立三维角色制作，取代此前全部角色制作暂停的范围；旧Live2D拼接原型继续保留，不继续在旧原型上追加动作。软件24小时优化与原截止时间保持。

## 目标与依据

角色就是用户提供照片中的奶龙，不是同风格替代物。以原照片的大头、圆润连贯身体、短粗四肢、黄色皮肤、浅色肚皮、绿边黑眼睛与笑嘴为依据。照片侧后方不可见区域属于补充设计，不能声称还原了原始官方三维模型。

选择Blender制作连续皮肤网格、材质、后续骨骼与动画。另一方案是重做Live2D分层美术；其优点是复用当前运行框架，但对转身、搬物和体积保持的制作要求更高。用户已选择三维路线。现有三套Live2D功能保留，运行时替换不是本阶段交付。

## 第一阶段交付

1. 原参考图只复制保存，像素保持。
2. 身体、头部与四肢融合为连续表面，眼睛、口腔、爪等附属物可以独立，但不能以可见球体接缝替代身体结构。
3. 保存可编辑 `.blend` 工程，提供正面、侧面及接近原图视角的实际渲染。
4. 核查身体连通性、渲染完成、源工程重开，记录实际结果；技术检查不能替代相似度和自然度验收。
5. 将完整造型与原照片供用户比较。外观未认可前，不扩大到完整动作库或生产接入。

## 后续阶段

外观确认后整理适合弯曲的网格与权重，制作骨骼、表情及呼吸/转头/迈步。再扩展文件搬运、打字、思考、等待、失败和停止动作，检查重心、接地、遮挡及过渡。最后在独立软件分支验证透明渲染、点击穿透、拖拽、缩放、屏幕边界和任务状态同步，再考虑发布；不能用静态渲染冒充可动角色。

## 工具与范围

采用Blender官方4.5 LTS便携版，下载和解压留在E盘项目忽略的工具目录，并核对官方SHA-256。使用Blender自带Python接口生成和检查可编辑场景。现有插件搜索没有Blender结果，MCP连接可后补，并非本阶段的前置阻塞。不上传参考图至第三方生成服务，不修改用户安装版本或真实数据。

参考：Live2D官方拆层教程及样例、Blender官方动画能力说明、GitHub `ahujasid/mcp-for-blender`。图生三维仅是可选粗模手段，本阶段不下载大型生成模型，不把生成网格直接认定为动画成品。
